# Data and GIS pipeline

## Data ownership

The simulation is not part of this Dashboard. The browser consumes prepared data checked into the repository.

| Kind | Examples |
| --- | --- |
| Dashboard source | `src/data/STAR_FARM CSV - Master file.csv`, `src/data/STAR_FARM CSV - Dữ liệu tổng.csv`, `src/data/indicators.csv`. |
| Prepared map source/runtime | `public/map-data/geometry.json`, scenario results, `manifest.json`, `soil-overlay.json`, boundary GeoJSON. |
| Generated application data | JSON under `src/data/`; map aggregates, soil layer JSON, and raster under `public/map-data/`. |
| External preparation input | STAR-FARM model outputs and geometry; supplied soil GIS; administrative-unit GeoJSON. |

Normal development and build do not regenerate data. Do not hand-edit generated JSON to change results.

~~~mermaid
flowchart TD
  CSV[Paired dashboard CSVs] --> Future[build-future-data.mjs]
  CSV --> Scenario[build-scenario-data.mjs]
  Future --> AppJSON[src/data/future-series.json]
  Scenario --> AppJSON
  Model[External model results and geometry] --> MapPy[build-map-data.py]
  MapPy --> MapSource[geometry scenarios currency manifest]
  MapSource --> Agg[build-map-aggregates.mjs]
  Agg --> MapRuntime[hashed aggregates and manifest]
  Shapes[External soil GIS] --> SoilPy[build-soil-overlay.py]
  MapSource --> SoilPy
  SoilPy --> Overlay[soil-overlay.json]
  Overlay --> Pack[build-soil-assets.mjs]
  MapSource --> Pack
  Pack --> SoilRuntime[layer JSON raster soil-manifest.json]
~~~

## Dashboard CSVs

`build-future-data.mjs` produces `src/data/future-series.json`. `build-scenario-data.mjs` produces scenario, economics, resources, environment, and seasonal JSON. The paired sources are English/USD and Vietnamese/VND; do not combine them to calculate counts or averages. `src/data/indicators.csv` owns bilingual glossary entries. `src/data/catalog.json` is descriptive metadata and is not regenerated by these commands.

Seasonal outputs use packed indexed rows and numeric arrays; `src/features/economics/seasonalData.ts` owns packing and unpacking. Preserve zeroes and missing values as different cases.

Scenario details reports the modeled period as 2027–2050 and its historical/current reference period as 2016–2022. The economics overview documents return on investment as mean net income divided by mean production cost, times 100; rows with no positive cost do not receive that ratio. Environment aggregation converts the source emission-intensity unit from kg methane/kg rice to kg methane/ton rice. The environment summary describes averages across four weather/resource combinations; AWD adoption is the share of model records using AWD, with changes shown in percentage points. Keep these definitions alongside their source calculations and do not generalize them to other chart denominators.

~~~powershell
npm run data:future
npm run data:scenarios
~~~

Generator validation is module-specific. Compare outputs and check paired source populations; successful generation alone does not prove complete record correspondence.

## Farming map

The checked-in `public/map-data/manifest.json` lists 16 scenario files. Each file covers 992 plots for years 2027–2050. The Python preparation script reads the original model checkout:

~~~powershell
python scripts/build-map-data.py --model-root "D:/path/to/STAR FARM"
~~~

It expects geometry under `includes/Dong Thap` and scenario files under `results/New Dong Thap/season/`. To refresh only the conversion from Dashboard source data:

~~~powershell
python scripts/build-map-data.py --currency-only
~~~

Then rebuild aggregate combinations with `npm run data:map-aggregates`. Plot IDs are positional associations between model columns and shapefile order, not cadastral IDs. Display outlines are simplified; plot area values use original projected rings. Historical source records do not independently prove geometry alignment. Do not treat plot results as ownership data.

Prepared geometry declares EPSG:32648. Preserve CRS, feature order, bounds, IDs, hashes, and references when replacing geometry. Dashboard summaries and selected plot/year data may represent different simulation populations.

## Soil and Land Use

The Python overlay builder clips supplied classifications to Dashboard display geometry. It requires Shapely 2.2 and external soil inputs:

~~~powershell
python scripts/build-soil-overlay.py --soil-root "D:/path/to/soil"
npm run data:soil
~~~

Layer names and classification fields are configured in `scripts/build-soil-overlay.py`. The Node packer reads `public/map-data/soil-overlay.json`, writes content-hashed per-layer JSON, updates `src/data/soil-manifest.json`, and creates the Land Use raster.

Land Use JSON retains per-plot category areas and unknown area but omits detailed vector feature paths. The generator renders those paths and plot outlines to a 3072-pixel lossless WebP. The browser displays that raster over shared plot geometry; statistics are not calculated from the image. Raster detail can be lower than a high-resolution drawing while area shares remain unchanged.

`scripts/build-admin-boundaries.py` prepares `public/map-data/admin-boundaries.geojson` from province and ward GeoJSON, reprojected to display CRS. It accepts the GeoJSON source root and output filename as positional arguments, for example `python scripts/build-admin-boundaries.py D:/path/to/admin-source public/map-data/admin-boundaries.geojson`. Its selected province folders and levels are declared in the script, so it does not process every administrative unit. Keep `admin-boundaries-LICENSE.txt`; verify names, extents, properties, and CRS when replacing this asset.

When map generation changes, check geometry and hashes, source overlay, layer files, soil manifest, raster filename, scenario manifest, and aggregate references. Deploy manifests and referenced hashed assets together; retain old hashes while cached manifests may refer to them.

## Scientific and geographic integrity

- Preserve units, periods, scenario codes, populations, categories, missing records, valid zeroes, and negatives.
- Keep USD/VND paths distinct. Map currency conversion is prepared from paired Dashboard production-cost observations and stored in `currency.json`; no live rate service is used.
- Plot-map harvest slots are chronological within each year/run. Dashboard seasonal aggregation uses its own timestamp/month rules; these definitions differ.
- Average harvest values using per-metric observation counts where present. Do not add harvest yield as annual production.
- Soil, flood-depth, acid sulfate-depth, and land-use layers are static classifications, not forecasts. Flood depth is not flood duration; acid sulfate depth is not pH. Land-use metadata alone does not establish its survey date.
- BAU versus 1Mha differences represent a package of conditions and practices; do not attribute all change to AWD.
- After regeneration, check categories, area totals, unknown areas, geometry, units, hashes, and manifest references.

Do not run `npm run data:all` as a routine check; it rewrites generated assets.
